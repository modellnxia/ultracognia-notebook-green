[ASSISTANT] Para gerar logs de uma aplicação Python hospedada no Railway, a estratégia mais eficaz e recomendada pela infraestrutura moderna de nuvem (12-factor apps) é direcionar os logs para a **saída padrão (stdout)** e para o **erro padrão (stderr)**. O Railway captura automaticamente tudo o que é enviado para esses fluxos e exibe no dashboard.

Aqui está o roteiro técnico para implementação:

### 1. Configuração do Módulo `logging`
Não utilize apenas o comando `print()`, pois ele não oferece níveis de severidade. Utilize a biblioteca padrão do Python:

```python
import logging
import sys

# Configuração básica
logging.basicConfig(
    level=logging.INFO,
    format='%(asctime)s - %(name)s - %(levelname)s - %(message)s',
    handlers=[
        logging.StreamHandler(sys.stdout) # Crucial: envia para o terminal que o Railway monitora
    ]
)

logger = logging.getLogger(__name__)

# Exemplos de uso
logger.info("Aplicação iniciada com sucesso.")
logger.error("Erro ao processar requisição.")
```

### 2. Flush de Logs
Em alguns ambientes, o log pode sofrer atraso (buffering). Para garantir que os logs apareçam em tempo real no dashboard do Railway, você pode forçar o Python a não utilizar buffer definindo uma variável de ambiente no Railway:
*   **Key:** `PYTHONUNBUFFERED`
*   **Value:** `1`

### 3. Visualização no Railway
Para acessar os logs gerados:
1.  Acesse o painel do seu projeto no **Railway.app**.
2.  Clique no serviço desejado.
3.  Vá até a aba **"Logs"**.
4.  Lá você verá tanto os logs de *Build* quanto os logs de *Deploy* (Runtime).

### 4. Dica Pro: Logs Estruturados (JSON)
Se você pretende escalar a análise, use logs em formato JSON. Isso facilita a filtragem futura em ferramentas de monitoramento:
```python
# Instale: pip install python-json-logger
from pythonjsonlogger import jsonlogger

logHandler = logging.StreamHandler(sys.stdout)
formatter = jsonlogger.JsonFormatter()
logHandler.setFormatter(formatter)
logger.addHandler(logHandler)
```

[ASSISTANT] Para visualizar os logs no Railway utilizando a **Estratégia 4 (Logs Estruturados em JSON)**, o processo é intuitivo, mas exige atenção a como a plataforma interpreta os dados.

Aqui está o passo a passo para visualização e o que esperar:

### 1. Caminho para o Painel de Logs
1.  Acesse o seu projeto no [Railway.app](https://railway.app/).
2.  Clique no **Serviço** específico que está rodando sua aplicação Python.
3.  No menu superior ou lateral do serviço, clique na aba **"Logs"**.
4.  Certifique-se de que a sub-aba **"Deployments"** (ou Runtime) está selecionada. É aqui que as saídas do seu código aparecem em tempo real.

### 2. Comportamento da Estratégia 4 (JSON) no Railway
Como você configurou o `python-json-logger`, o Railway não exibirá mais linhas de texto comuns (ex: `INFO:root:Mensagem`), mas sim objetos JSON puros.
*   **O que você verá:** Cada linha será um objeto como `{"asctime": "2023-10-27...", "levelname": "INFO", "message": "Conexão estabelecida"}`.
*   **Vantagem:** O Railway possui um campo de busca (Search) no topo dos logs. Com JSON, você pode filtrar por termos específicos que agora são chaves fixas no seu log, facilitando a depuração.
